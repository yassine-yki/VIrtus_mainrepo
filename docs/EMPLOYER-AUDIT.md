# Additional employer feed audit

Checked **2026-10-25**, using the repository's existing SmartRecruiters, Greenhouse and Lever collectors against public employer ATS endpoints. This audit covers **20 additional employers**, excluding the six existing employer groups. Counts are a dated observation, not a promise of current vacancies.

**Result: 9 qualifying private feeds, 183 records and 183 distinct URL-based `group_key` values.** The other 11 feeds returned no eligible Morocco jobs and remain disabled for later rechecking. All 20 selected endpoints completed the relevant collection successfully. **None of these employer sources is approved for public republication.**

The machine-readable evidence and registry defaults are in `src/lib/audited-employers.json`. The secret-free local snapshot is `data/audited-catalog.json` (ignored by Git). Each JSON entry records the precise endpoint, check timestamp, counts, pagination result, careers page, reuse status, and error field.

## What was verified

- SmartRecruiters: the global count is its `totalFound` metadata from an unfiltered single-record query; only the **complete `country=ma` result set** is paginated and detailed. Inetum's 131 records required two posting pages plus 131 detail reads. Global counts do not imply that all global records were downloaded.
- Greenhouse: its board jobs response was read once with `content=true`, then every record passed through the existing normalizer. Lever: pages of 100 were read through the first shorter page, with repeated IDs rejected. Yassir required two pages.
- Existing normalization enforces explicit Morocco/city eligibility, HTTPS original links, plain-text descriptions, valid stable IDs, and contract/workplace normalization. Generic “remote”, EMEA or Europe eligibility alone does **not** count as Morocco coverage.
- Disabled zero counts describe the tested ATS feed only, not all of an employer's vacancies elsewhere. SEGULA's current careers site uses a broader system than the one-record SmartRecruiters feed; it is not scraped here. An empty historical board such as Jellyfish is retained for rechecking and is not claimed as a current production integration.
- Counts are before combining with existing sources; the 183 normalized records have 183 distinct `group_key` values within this audit. The main import must calculate the combined catalog count instead of adding counts blindly.

## Access versus reuse

The primary evidence links above establish employer identity, endpoint access and technical Morocco coverage. **No explicit licence or written permission for third-party commercial republication was established for any of these 20 employers.** Every JSON entry therefore sets `publicationStatus: "pending"`; successful access must not automatically change it to `approved`.

This is an evidence status, not a claim that permission is either granted or prohibited. Before public approval, record the exact applicable licence/terms or employer agreement, its URL/date, permitted fields and attribution requirements in source records and operations documentation. No permission request was sent.

## Recheck procedure

Run the existing collector with one source selected after reviewing any changed provider/careers identifier. A zero-result disabled source may be temporarily enabled for an owner-authorized recheck; retain publication status as pending. Only enable ongoing collection when full pagination, identifier validation and Morocco filtering pass. API or parsing failure must leave existing listings intact and must never be reported as a successful empty feed.
